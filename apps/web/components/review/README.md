# Staff review preview

`ReviewInbox({ entries, decide, memberLabels? })` consumes canonical ReviewQueueEntry projections and a callback from ReviewDecision to Promise<Result<ReviewOutcome>>. Labels are visual strings only. Neither props nor hidden navigation authorize evidence access. These components are preview presentation; production routes must first resolve verified sessions/current tenant membership server-side.

The selected entry must belong to the visible list. Any filter/search change clears selection, evidence and actions. Detail identity includes source ID, independent review revision and filter state, resetting reason/error/outcome on source or filter change. Late callback results remain in the unmounted old detail, not the new source. Source/proposal text and evidence quotes use React text nodes, never HTML injection, URL fetching or tool execution.

Candidates remain unverified and show source revision, review aggregate revision, quote spans and explicit unknown values. Commands use entry.revision as expectedRevision, never source.revision. Text edits/linking/corrections are unavailable. Unknown/unresolved candidates block acceptance; rejection needs a reason. Pending decisions lock both buttons; transient errors retain the reason and command identity for retry; conflicts lock decisions and require reload. Simulated completion focuses its result and explicitly claims no ledger/need/assignment/alert effect. Rejection is not withdrawal of provisional alerts.

Fixtures are independently authored here from selected canonical synthetic source text plus two local synthetic sources. Runtime reviewQueueEntrySchema parsing checks tenant/source/revision agreement. They do not invoke D's adapter or derive canonical expected results. Proposal quote offsets are UTF-16 spans relative to the preserved source. The review fixture with source revision 1 and review revision 12 deliberately catches revision confusion in the controlled callback; success yields preview revision 13.

A approved the shared-visit boundary in board answer 9d5635e1: retain distinct Mira/Sol candidates (60 minutes each), show an unresolved possible-existing Sol contribution warning, disable accept until reconciliation. No local ledger DTO, aggregation, link action or double-count prevention claim. Real existing-vs-new projection and reconciliation require later A/B/D work. The synthetic scenario does not declare the canonical oracle's current ledger state.

`ReviewPreview` exposes simulated success, conflict, unavailable and empty states with a bounded local pending delay. No persistence, API or notification occurs. Fixture source data is imported on the server page; the client adapter receives only its passed entries/labels. `/workspace/inbox` is force-dynamic and calls notFound outside development before rendering content. No production auth bypass, M1/M2 acceptance or real review effect is claimed.

Scoped Playwright specs cover selection/filter/empty state, safe source rendering, separate contribution candidates, unknown/90-minute values, canonical command revisions, pending/race/reason/error/conflict behavior, and four viewport widths. Source, import/photo, ledger, actual tenant-denial and provider integration remain separate tasks. Screen-reader and non-Chromium testing are not implied by these checks.
