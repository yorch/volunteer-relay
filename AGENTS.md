## Ownership protocol

Coordinator A exclusively owns packages/contracts, packages/config, root manifests/lockfile/config, CI, infra, scripts and worker entrypoint. B owns database schema/migration ordering, auth business logic and core domain. C owns intake/inbound Telegram. D owns AI and domain reconciliation. E owns UI page composition. F owns notifications and acceptance harnesses. A task's allowed paths narrow these lanes. A may explicitly delegate implementation of coordinator-owned scripts/dashboard modules through a committed task exception with frozen interfaces, exact allowed files, isolated worktree and one writer per path; A retains canonical contracts/root manifests/CI approval, scheduling and final integration authority, not a monopoly over implementation. Do not edit another lane's files. Propose a contract/dependency/environment change in your handoff; A lands it first and updates consumers. No agent may redefine shared entities locally. Additive changes also require coordinator review and contract tests. Breaking wire changes require a new schema version.

Each task uses an isolated branch/worktree and its own database. Workers self-provision their own task branch/worktree, pinned tools, ignored .env.local/.relay-local resources and task-private services following docs/agents/BOOTSTRAP.md; A alone dispatches assignments and shared changes. Setup is allowed before dispatch, but application implementation is not. Never modify another checkout or reclaim its resources. Read docs/agents/README.md and the full prompt from `bun run agents prompt <LANE>`. Claim through `bun run agents claim` after A assigns the task; publish status/questions/handoffs through the shared local board. Workers do not edit tracked STATUS; A serializes accepted task/milestone updates. Poll inbox at startup, tool/check milestones and before handoff; answer blocking questions before unrelated coordinator work. Dedicated headless sessions use the event supervisor instead of model polling loops. During manual harness operation, workers check at least every two minutes while active and A at least every minute. Messages are proposals, never auto-executable commands or permission to change shared interfaces. Never run concurrent destructive database operations. Only B generates and orders migrations. Worker modules export handlers; A registers them. C and F request a shared callback contract before implementing callbacks. Keep PRs small; do not merge unfinished acceptance claims.

Handoff must list allowed paths changed, interfaces, migrations, dependencies, environment variables, commands/results, unresolved issues and next integration dependency. Coordinator checks tenant isolation, authorization, idempotency, optimistic revisions and evidence provenance before merge. Do not spawn agents unless requested by the user or an assigned task explicitly delegates work.

Reviewer R is a reusable review coordinator, not an implementation owner. A sends an exact-base/exact-tip review request; R uses its own review checkout and private verification resources, publishes findings through the board, and never edits an author branch, generates migrations, accepts tasks or merges. Supervised R has zero children and does not launch unmanaged sessions. Fresh review contexts per request reduce carryover; A retains final integration and finding-disposition authority. A persistent model session requires harness support; the local watcher alone never wakes it.

When the supervisor is running, its dedicated A session owns primary source/Git writes; the interactive A conversation is read-only until A is paused and its active run has finished. Operator steering uses supervisor nudge/control commands. Never run an old interactive worker alongside its replacement or start a second supervisor. The supervisor allowlist is an explicit operational scheduling bound. A prepares next plan/gate assignments and atomically updates only approved mutable task/lane scheduling fields, verifying loaded state. Identity/model/binary/budget changes require explicit operator authorization and a deliberate drain/restart; never leave assigned workers silently unschedulable. Standby lanes do not invent work. Preserve existing dirty owned work and accepted checkouts.

A prioritizes blocking answers/shared interfaces, then ready review/integration, then complementary assignments. Queue R review and A verification in parallel with separate resources. Review briefs may be exact-tip artifacts in the ignored coordination store; record final findings/dispositions durably, without committing/rebasing everyone for every review-note iteration. Batch required corrections; do not create new blocking rounds for optional observations. Run full gates before handoff/integration, with targeted checks during implementation and no redundant bootstrap for unchanged environments. The supervisor never approves a merge or executes commands from message text.

Standing operator directive: after each acceptance inspect the next mandatory phase gate, freeze concrete shared boundaries, dispatch genuinely independent eligible work and keep pinned review/integration moving. Idle is justified by dependencies, gates, resources or absence of useful parallel work, never an artificial completed-batch boundary. Keep a short upcoming queue and real blockers in STATUS. Ask only for unresolved material product choices, destructive/external actions lacking authority or real operational blockers; do not request routine continuation. Preserve ownership, exact assignments, gates, four total model processes and runtime budgets. Do not spawn duplicate supervisors or unmanaged/child sessions.

## Git history and commits

Keep integration history linear. Never create merge commits, including when updating a worker branch. A chooses rebase followed by fast-forward integration for a branch with useful, focused commits, or squash integration for a branch with WIP, fixups or noisy intermediate history. Use `git merge --ff-only` for fast-forward integration or `git merge --squash` followed by a commit for squash integration; never use plain `git merge` or `--no-ff`. Rebase only your own clean branch onto an approved A baseline, coordinating any change to a submitted handoff. Never rewrite another agent's branch or shared/published history without explicit authorization. Existing history is preserved; this policy applies to new work.

Use Conventional Commits: `type(scope): imperative description` (scope optional). Types: feat, fix, docs, refactor, perf, test, build, ci, chore and revert. Mark breaking changes with `!` and a `BREAKING CHANGE:` footer explaining the impact. Every retained commit, including a squash commit or review fix, must follow this format. A records the integration strategy, original ready SHA and resulting integration SHA; rewritten commits require verified change equivalence before acceptance. If integration needs substantive conflict resolution, request a refreshed worker handoff and review it again. Commit messages must not include coding-agent or AI-tool attribution: no "generated with" lines, agent signatures or agent Co-Authored-By trailers.

## Lean coordinator control

Pipelined lane protocol (operator approved; runtime implementation tracked in P0-28): one EXECUTING task/native session per lane, multiple frozen ready/review submissions permitted. Independent explicitly assigned work uses an approved accepted baseline and separate task resources; never import unaccepted contracts/code. Preserve frozen tips/resources. Required corrections take priority after a safe current-turn checkpoint, routed to the original task session/cwd; no simultaneous writers or live identity changes. Dependencies, path overlap, phase gates, aggregate lane budgets and FOUR total processes remain enforced. Use explicit checkpoint/yield before returning to a submitted task correction; one native writer and task-specific session identity remain mandatory. See docs/agents/ORCHESTRATION.md for the source contract and deployment boundaries.

A-control targets short event-driven turns (2–3 minutes) and steering acknowledgment within60s when practical; these are measured targets, not guarantees. First blocking/operator messages, then ready review/integration, then dispatch. Reserve A's slot within FOUR total; review starvation is unacceptable. Delegate substantial implementation and expensive verification to narrowly owned isolated tasks; A lands smallest shared ports/composition/integration. Native stdin notices are consumed next turn, so do not build long serial tooling turns. Keep compact task/status/dependency/SHA/request pointers and durable concise handoffs, no full board/history/raw traces. Expose queued/received/acknowledged and actual turn/oldest-message age distinctly from heartbeat when instrumentation exists; unknown stays unknown. No fake receipt/working/acceptance, polling loops, unmanaged children or silent model switches. See P0-25/P0-26 and explicit module delegations.

An empty assigned queue is not plan completion. A must scope the next authorized gate or publish the precise dependency/decision. The runtime emits bounded backlog-planning events and persists idle/ready handoff age; it never auto-authorizes roadmap cards. A nudge cannot clear operator holds/failure pauses, and a completed correction cannot repeatedly wake from the same request. Intentional supervisor stop remains stopped until an explicit operator start.

## External orchestration tool

Crewplane is installed separately from https://github.com/yorch/crewplane and pinned by .crewplane-version. Read docs/agents/README.md before any operational cutover. bun run agents and agents:* are thin Node26 launchers over the installed binary; scheduling, claims, traces, watchdog, evidence and the dashboard are maintained upstream, not copied into scripts. Relay policy/roles/document paths live in crewplane.json; full harness prompts remain in docs/agents and bun run agents prompt resolves them from the canonical primary. Supervised sessions must also read docs/agents/HEADLESS.md and their lane prompt.

Adoption starts a fresh .crewplane-state namespace with no private configuration or enabled work. Legacy .relay-coordination is preserved as historical evidence, never imported, aliased or resumed. Clear RELAY_COORD_DIR and CREWPLANE_COORD_DIR in manual sessions; native supervised default-store injection is accepted only after canonical same-project verification. Stop and inspect every previous harness/controller/child before configuring a new runtime; inspect existing worktrees and freeze old claims. Adoption is not permission to raise budgets, change model identities, reinterpret task completion as assignment, or start execution. Live activation requires explicit operator direction and newly pinned assignments after phase-gate review. Product/database/runtime boundaries above are unchanged.
