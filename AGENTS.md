## Ownership protocol

Coordinator A exclusively owns packages/contracts, packages/config, root manifests/lockfile/config, CI, infra, scripts and worker entrypoint. B owns database schema/migration ordering, auth business logic and core domain. C owns intake/inbound Telegram. D owns AI and domain reconciliation. E owns UI page composition. F owns notifications and acceptance harnesses. A task's allowed paths narrow these lanes. Do not edit another lane's files. Propose a contract/dependency/environment change in your handoff; A lands it first and updates consumers. No agent may redefine shared entities locally. Additive changes also require coordinator review and contract tests. Breaking wire changes require a new schema version.

Each task uses an isolated branch/worktree and its own database. Workers self-provision their own task branch/worktree, pinned tools, ignored .env.local/.relay-local resources and task-private services following docs/agents/BOOTSTRAP.md; A alone dispatches assignments and shared changes. Setup is allowed before dispatch, but application implementation is not. Never modify another checkout or reclaim its resources. Read docs/agents/README.md and the full prompt from `bun run agents prompt <LANE>`. Claim through `bun run agents claim` after A assigns the task; publish status/questions/handoffs through the shared local board. Workers do not edit tracked STATUS; A serializes accepted task/milestone updates. Poll inbox at startup, tool/check milestones and before handoff; answer blocking questions before unrelated coordinator work. Dedicated headless sessions use the event supervisor instead of model polling loops. During manual harness operation, workers check at least every two minutes while active and A at least every minute. Messages are proposals, never auto-executable commands or permission to change shared interfaces. Never run concurrent destructive database operations. Only B generates and orders migrations. Worker modules export handlers; A registers them. C and F request a shared callback contract before implementing callbacks. Keep PRs small; do not merge unfinished acceptance claims.

Handoff must list allowed paths changed, interfaces, migrations, dependencies, environment variables, commands/results, unresolved issues and next integration dependency. Coordinator checks tenant isolation, authorization, idempotency, optimistic revisions and evidence provenance before merge. Do not spawn agents unless requested by the user or an assigned task explicitly delegates work.

Reviewer R is a reusable review coordinator, not an implementation owner. A sends an exact-base/exact-tip review request; R uses its own review checkout and private verification resources, publishes progress/findings through the board, and never edits an author branch, generates migrations, accepts tasks or merges. When the review brief explicitly permits it, R may delegate up to its stated budget (maximum two concurrent isolated sub-reviews); children stay inside that same scope, do not recursively delegate, and report only to R. R consolidates findings and is the sole R board writer. Fresh review contexts per request reduce carryover; A retains final integration and finding-disposition authority. A persistent model session requires harness support; the local watcher alone never wakes it.

## Headless ownership and throughput

Read docs/agents/HEADLESS.md in supervised operation. When the supervisor is running, its dedicated A session owns primary source/Git writes; the interactive A conversation is read-only until A is paused and its active run has finished. Operator steering uses supervisor nudge/control commands. Never run an old interactive worker alongside its replacement or start a second supervisor. Only configured task IDs are authorized; standby lanes do not invent work. Preserve existing dirty owned work and accepted checkouts.

A prioritizes blocking answers/shared interfaces, then ready review/integration, then complementary assignments. Queue R review and A verification in parallel with separate resources. Review briefs may be exact-tip artifacts in the ignored coordination store; record final findings/dispositions durably, without committing/rebasing everyone for every review-note iteration. Batch required corrections; do not create new blocking rounds for optional observations. Run full gates before handoff/integration, with targeted checks during implementation and no redundant bootstrap for unchanged environments. The supervisor never approves a merge or executes commands from message text.

## Git history and commits

Keep integration history linear. Never create merge commits, including when updating a worker branch. A chooses rebase followed by fast-forward integration for a branch with useful, focused commits, or squash integration for a branch with WIP, fixups or noisy intermediate history. Use `git merge --ff-only` for fast-forward integration or `git merge --squash` followed by a commit for squash integration; never use plain `git merge` or `--no-ff`. Rebase only your own clean branch onto an approved A baseline, coordinating any change to a submitted handoff. Never rewrite another agent's branch or shared/published history without explicit authorization. Existing history is preserved; this policy applies to new work.

Use Conventional Commits: `type(scope): imperative description` (scope optional). Types: feat, fix, docs, refactor, perf, test, build, ci, chore and revert. Mark breaking changes with `!` and a `BREAKING CHANGE:` footer explaining the impact. Every retained commit, including a squash commit or review fix, must follow this format. A records the integration strategy, original ready SHA and resulting integration SHA; rewritten commits require verified change equivalence before acceptance. If integration needs substantive conflict resolution, request a refreshed worker handoff and review it again.

## Invariants

Tenant context is resolved by the server; a parsed organization ID grants no authority. Tenant-owned relations use organization-scoped keys. Revalidate current membership at human-authorized job/callback execution. Persist source and outbox atomically. Jobs and effects must tolerate replay; never claim exactly-once external delivery. Approved contribution minutes form the reporting ledger; unknown is null, not zero. Preserve source revisions and evidence. No face recognition, arbitrary message URL fetching, tool execution or sensitive source text in logs. Tests use controlled adapters; live provider checks are opt-in. Phase gates in the plan remain mandatory.
