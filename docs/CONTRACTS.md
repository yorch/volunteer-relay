# Contract baseline v1

Canonical schemas and service ports: `packages/contracts/src/index.ts`. Runtime schemas are strict and wire dates use ISO instants with offsets; local activity dates preserve day/unknown precision. Evidence identifies the proposed field it supports. Evidence offsets are JavaScript UTF-16 string indices, half-open [start,end), relative to the exact preserved source revision. Attachment observations never establish identity or duration. IDs are opaque nonempty strings, organization-scoped in storage. Context is trusted only after AuthorizationService resolution; all repository/service calls still enforce matching tenant and permission. Not-found responses conceal cross-tenant existence.

SourceRepository.accept owns one transaction for source plus outbox. Its idempotency key is unique within organization/channel identity; identical replay returns the prior receipt; a changed payload with the same key is CONFLICT. Revisions and explicit edit identity preserve evidence. A receipt means durable intake, never approved business data. HTTP adapter: POST source uses the SourceEnvelope body and server-resolved context, returns 202 Receipt; error envelope maps UNAUTHENTICATED=401, FORBIDDEN=403, NOT_FOUND=404, VALIDATION=422, CONFLICT=409, RATE_LIMITED=429, DEPENDENCY_UNAVAILABLE=503. No routes implement this yet.

Events carry stable event IDs, tenant, actor, aggregate revision and correlation ID. Outbox consumers deduplicate event ID plus handler name; external acceptance is not human acknowledgment. Review decisions use expectedRevision and idempotencyKey. Model proposals are untrusted candidates, never authorization or approved records. All unknown fields are explicit nulls or unresolved entries. Notification recipients are resolved within tenant; appPath must be an internal authenticated deep link. Delivery transport does not decide routing.

This is the frozen starter interface, not a claim that every later use case has a complete port. Need lifecycle commands, reporting queries, Telegram callbacks, upload writes, policy edits and edited review payloads require an A-owned additive contract task before consumer implementation. Agents may design proposals independently but must not create conflicting local interfaces. Schema parsing cannot validate database ownership, membership, quote fidelity, timezone semantics or policy; those checks belong to implementing services.
