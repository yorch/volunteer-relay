# Explicit Crewplane supervision

Read README.md in this directory and the primary AGENTS.md first. Crewplane is pinned by .crewplane-version and installed separately. The adoption PR neither starts processes nor migrates .relay-coordination. A owns integration; no interactive writer may race supervised A. Workers/reviewers must read their Relay lane prompt in docs/agents/prompts; the external runtime's generic prompts do not replace project setup, tenant invariants or acceptance gates.

Before activation, the operator verifies every old harness/controller/child stopped, preserves old claims/resources, chooses exact model/binary/budgets and confirms current stopped state. Start from crewplane-runtime.example.json, replacing both deliberate placeholders. All lanes are disabled and allowedTasks is empty. Do not copy old config/session/PID/hold state or infer approval from an old enabled lane. Configure explicitly using `bun run crewplane configure --file /absolute/private/runtime.json`, then `bun run crewplane doctor`. Real installed harness/version/provider compatibility remains an opt-in separate check; doctor is not a credential/provider test.

A publishes committed scoped cards, scopes and exact-base assignments, and lists only phase-gate-approved task IDs in the private config. Keep at most four total model processes with A capacity reserved; R and V are on-demand exact-SHA verification with no children. Codex supports implementation; pi is no-tools and is not a worker substitute. Claude/OpenCode remain manual harnesses until upstream supplies accepted adapters. No model switches, budget increases or identity changes without explicit operator authorization and a deliberate drain.

Start one foreground controller only after explicit activation: `bun run agents:supervisor start`. Use the installed binary for native execution; the adapter forwards signals to drain before exiting. Worktrees and private run state are Crewplane-owned under .crewplane-local/.crewplane-state; worker app services still use task-private .relay-local resources. Read compact `bun run agents brief`/inbox at turn start and milestones. End waiting turns rather than model polling loops. Questions are task-scoped and replies stay on their original thread. Supervised A must proactively answer blockers, route exact-SHA review/corrections, verify/integrate then dispatch genuinely eligible disjoint work; idle needs an actual dependency/gate/resource reason. Ready is frozen and not accepted; Git integration remains an explicit A action.

Commands: `bun run agents:supervisor status`, `pause --lane A`, `nudge --lane A --text 'steering'`, `resume --lane A`, `retry --lane B`, `stop`. Nudge never clears a hold/failure. Stop/SIGTERM request drain, not instant replacement. Wait for running:false, settled child groups/traces and released lease. Live or unverified old children block replacement; never delete a lease to force startup. Cleanup acknowledgement requires actual inspection/termination, not a dashboard button. Rollout drains while retaining intent but does not start a replacement. Startup-only changes require explicit safe reconfiguration; no stale assignment may be left outside the loaded allowlist without a truthful blocker.

Defaults remain four concurrent processes, 10-second checks, 25-minute runs and 20 runs/lane/hour. They are run/time limits, not token/dollar budgets. Missing usage dimensions stay unknown. Failures, invalid native output, required operator decisions and no-progress pauses require explicit recovery; watchdog observation cannot override them. See upstream docs/USAGE.md for current command details and verified lifecycle limits.
