# Frozen scheduling reload policy v1

C explicit exception owns ONLY scripts/config-reload.ts and scripts/config-reload.test.ts; A keeps supervisor loop/state/dashboard integration. Pure backend module, no filesystem/process/supervisor/config mutation. Import Config as a TYPE only. Export `evaluateSchedulingReload(current:Config,candidate:unknown,validate:(value:unknown)=>Config):{config:Config,outcome:'applied'|'unchanged'|'invalid'|'deferred',errorCode:null|'INVALID_CONFIG'|'RESTART_REQUIRED'}`.
Validate whole candidate with injected validator, catch failures without raw exception/details; retain current exact last-known-good. Only allowedTasks and enabled booleans are hot mutable. All root/binary/binaries/model/harness/epoch/permission/budget/interval fields immutable. Adding a lane with only enabled is permitted with existing default Codex identity; any new non-enabled settings defer. Immutable difference means retain current and RESTART_REQUIRED; no partial hidden harness/model interpretation. No mutation of caller objects, no message-derived code. Reordering/equivalent config should not create repeated false changes. Disabling active lane affects only future scheduling: helper never interrupts children. A integration will publish loaded fingerprint/error and re-read atomic file between passes.
Tests: enable/disable/new default lane/task addition, equivalent reordering, malformed candidate/validator throw with private sentinel, forbidden binary/harness/model/budget change, deep mutation preservation, absent optional legacy fields and recovery. No live config/model change. Root verify, exact clean tip. Own isolated task worktree, no DB/browser/provider needed. Four total process cap and review priority remain.
