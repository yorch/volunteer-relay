## Resolved in the cleanup pass (2026-11)

- **UIF-10 (mostly):** `Select` restores itself on `form.reset()` (unless the reset is cancelled), emits bubbling `input`/`change` from a mirror input so form-level `onChange` works, and a label click only focuses it. Ledger and import workarounds are gone; admin and needs keep their resets because they use controlled Selects. **Still open:** native `required` validation (hidden/readOnly inputs are barred from constraint validation, so forms keep their JS validation) and a listbox accessible name (breaks `getByLabel`).
- **UIF-11:** all 1,887 literal `var(--relay-x, fallback)` fallbacks are stripped; `components/css-tokens.test.ts` fails on new ones and on undefined `--relay-*` tokens (`--relay-canvas` and `--relay-surface` were undefined and only worked through fallbacks).
- **UIF-12:** shared card surface in `components/card.module.css` (`:where(.surface)`), shared page/heading rules in `product/page.module.css` (via `composes`), and nine local `Card` wrappers removed.
- **UIF-13:** Biome `noDescendingSpecificity` warnings are at zero.
- **UIF-14:** 900, 640 and 1100 px breakpoints moved to the contract set (1023, 760, 1024). Visible effect: collapsed admin/operations layouts now apply up to 1023 px, the overview grid switches at 1024 px, the roster card layout applies up to 760 px. `needs` and `retention` keep 1023 as the exact complement of 1024. Check at 1024 px in the sweep (the sidebar is also wider there, see UIF-15).
- **UIF-15:** the shell uses `--relay-sidebar-w` (15.5rem, 13.5rem at 761 to 1023 px); the local variable is gone.
- **UIF-16 (part):** command palette locks body scroll; Select option keys tolerate duplicate values. The settings-bar `scroll-margin` for textarea/select triggers is still open.
- **UIF-20 (partly):** the skeleton shape follows the last known role (`localStorage` `relay.shellShape`). On a hard refresh the server HTML is still the staff shape, so a volunteer sees staff, then volunteer, then the real shell. Fixing that needs a neutral SSR skeleton or a role cookie.
- **UIF-21 decided:** no hover/focus preview in the inbox; the shared helpers stay because the dev review preview uses them.
- **UIF-22:** `--relay-accent-strong` (`#a8690f`, 4.5:1 on white) replaces marigold for informative rules and borders on light surfaces; marigold remains on the dark sidebar and in fills.
- **UIF-23 decided:** both links stay.
- Fixed on the way: the summary "Compact" density toggle had no effect (specificity/order).

## Process lessons (so we do not relearn them)

- **Dev-server cache.** Running `bun run typecheck` or `bun run verify` and then `bun run test:e2e` has repeatedly produced spurious e2e failures: pages never finish loading, Next logs a `[Fast Refresh] rebuilding` then full reload loop, and single-shot assertions fail. Deleting `apps/web/.next-e2e` before the e2e run fixes it (also `apps/web/.next` after a build). The root cause is not proven; a likely contributor is Next rewriting `apps/web/next-env.d.ts` for whichever build directory it last served. Worth a small root-cause fix.
- **Check exit codes, not grepped output.** A chained `verify; e2e` command once looked green because the grep for test counts matched nothing, while `verify` had actually failed on lint. Always record each command's exit code.
- **Do not edit files while an e2e run is using the same tree** (HMR reloads cause false failures), and rebase only between runs.
- **e2e ports.** Use a distinct `PLAYWRIGHT_PORT` per worktree; other sessions run their own servers.
- **Specs are the contract.** Strict-mode Playwright counts hidden elements: new visible text must not duplicate an asserted string, and accessible names (for example nav links) must stay stable. Nav counts are exposed through `aria-describedby` for that reason.
- **Look at screenshots.** Passing specs missed an invisible primary button and stretched badges. Add visual-regression screenshots for key screens as part of UIF-01.
