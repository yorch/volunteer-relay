This file is a backlog, not a plan of record. It does not edit [`../STATUS.md`](../STATUS.md); the coordinator decides which items become scoped tasks and schedules them.

## Process lessons (so we do not relearn them)

- **Dev-server cache.** Running `bun run typecheck` or `bun run verify` and then `bun run test:e2e` has repeatedly produced spurious e2e failures: pages never finish loading, Next logs a `[Fast Refresh] rebuilding` then full reload loop, and single-shot assertions fail. Deleting `apps/web/.next-e2e` before the e2e run fixes it (also `apps/web/.next` after a build). The root cause is not proven; a likely contributor is Next rewriting `apps/web/next-env.d.ts` for whichever build directory it last served. Worth a small root-cause fix.
- **Check exit codes, not grepped output.** A chained `verify; e2e` command once looked green because the grep for test counts matched nothing, while `verify` had actually failed on lint. Always record each command's exit code.
- **Do not edit files while an e2e run is using the same tree** (HMR reloads cause false failures), and rebase only between runs.
- **e2e ports.** Use a distinct `PLAYWRIGHT_PORT` per worktree; other sessions run their own servers.
- **Specs are the contract.** Strict-mode Playwright counts hidden elements: new visible text must not duplicate an asserted string, and accessible names (for example nav links) must stay stable. Nav counts are exposed through `aria-describedby` for that reason.
- **Look at screenshots.** Passing specs missed an invisible primary button and stretched badges. Add visual-regression screenshots for key screens as part of UIF-01.
