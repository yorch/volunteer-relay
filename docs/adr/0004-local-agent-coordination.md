# ADR 0004 — Harness-neutral local agent coordination

Accepted 2026-11-07. Start with four active sessions: A coordinator, B identity/domain, D extraction and E visual foundation. C/F are logical lanes activated when scoped work is ready or another lane finishes/waits. Four is an initial throughput hypothesis based on the serial persistence/integration path, revisited after two accepted slices; the plan still supports up to six sessions when coordination capacity warrants it.

Use Git linked worktrees for code isolation and a dependency-free Node CLI over an ignored, shared local folder discovered from Git's common directory. One immutable message file per event avoids concurrent appends; atomic exclusive publication prevents duplicate task claims. Mutable per-task progress is single-writer, with separate coordinator acceptance. Six full startup prompts concatenate common instructions and a lane-specific prompt so no harness-specific implicit context is required. Shared contracts, dependencies, migrations and milestone status retain their existing single owners.

The tool does not launch harnesses, auto-execute messages, merge or authorize application work. Messages are proposals, identity flags are advisory, polling is required, and the local folder is not distributed/durable coordination infrastructure. No auto-expiry/claim stealing. Coordinator-controlled release archives abandoned task state only after the old writer is stopped. Durable decisions go into tracked contracts/ADRs/cards/STATUS; task-ready is distinct from accepted integration. No dependency or product interface changes are needed.

History policy amendment (2026-11-07): retain linear integration history and use Conventional Commits. A selects rebase plus fast-forward for meaningful commit sequences or squash for noisy/WIP sequences. Do not create merge commits, including worker baseline updates. Preserve existing history. Acceptance retains the original ready SHA and resulting integration SHA; rewritten integrations require an explicit integration base and equivalent aggregate binary diffs, while squash produces one commit. Divergent patches require a refreshed reviewed handoff. This tooling verifies mapping, not behavioral correctness; coordinator review and tests remain mandatory.
