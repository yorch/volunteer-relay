# ADR 0007 — Bounded event-driven headless orchestration

The operator approved replacing all external worker/reviewer harnesses with dedicated headless sessions and confirmed old B/E/D/R harnesses stopped. The local watcher alone cannot wake a model. A Node supervisor now invokes installed Codex non-interactive mode with saved CLI authentication and configured model defaults; future harness adapters can be added after equivalent session/permission behavior is verified. No private old conversations or credentials are inspected.

Use explicit native thread IDs, never --last. One supervisor/store and one run per lane/worktree; preserve existing claims/dirty work. Config bounds authorized task IDs, concurrency (4), event interval (10 seconds), per-run time (25 minutes) and per-lane hourly runs (20). C/D/F remain on demand. Questions/answers, new assignments, ready tips and run failures trigger work; normal progress chatter does not. Events coalesce during active runs. New R requests get fresh contexts. Failure/timeout/operator-needed/no-progress pauses require inspection/control; the supervisor never mutates application status or auto-merges.

Codex --approve-for-me selects workspace-write and routes escalations through automatic review. Installed CLI rejects combining it with --sandbox, so use --approve-for-me alone, with explicit writable primary directory access for shared board/Git metadata. No danger/bypass flags. A real isolated scratch test verified writing/committing a synthetic file, structured final output and explicit-ID resume. This is not an authorization bypass; automatic review can still reject an operation and the lane must report it.

Dedicated A owns primary writes after handover; interactive A becomes a read-only status/operator-control channel. Pause A and wait for its current run before taking writes back. Other roles use separate worktrees/DBs; author-ready state freezes code. R reviews and A independently verifies concurrently; final disposition/acceptance remains A's responsibility. Exact-tip review briefs may be ignored run artifacts referencing tracked policy, reducing bookkeeping-only commits and rebases. Shared contract changes and final decisions stay tracked.

Run logs/state/results are private ignored files. Logs cap at 20 MiB/run and 20 runs/lane. Native usage counts are recorded without claiming dollar cost. No continuous model polling, arbitrary board-supplied commands, automatic new-phase scope or hidden model overrides. An owning administrator can stop/drain sessions; restart refuses a still-live recorded child PID and preserves artifacts.
