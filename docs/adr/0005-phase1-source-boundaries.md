# ADR 0005 — Source persistence and fixture UI boundaries

Accepted 2026-11-07 for the second-wave scoped slices. M1 remains incomplete; these assignments do not bypass M1/M2 gates.

B first implements SourceRepository accept/get with transactional source/outbox storage. Canonical idempotency uniqueness is organization + channel + channelIdentity + idempotencyKey. An identical canonical envelope replay returns the stored original receipt, including its correlation ID; changed payload under that same key is CONFLICT. Compare validated complete envelope content independent of JSON object property order, preserving array order, original payload and all evidence values. A caller retries with the same envelope (including receivedAt), not reconstructed server timestamps. Current membership/authority is checked before returning a replay.

Source identity is organization + sourceId; revisions are positive, immutable and sequential. First revision is 1 with replacesRevision=null. Each later revision replaces the current immediately preceding revision, retaining stable channel/channelIdentity/externalMessageId and author mapping; changed-author reassignment needs a later reviewed command. Serialize conflicting edits and require tenant-scoped uniqueness of channel/channelIdentity/externalMessageId/revision, so another sourceId cannot impersonate the same external message revision. A reply references an existing source in the same tenant. Membership IDs on mapped authors must exist in that tenant at acceptance. Historical authorship survives later membership removal; an immutable source revision must not hold a live-member foreign key that blocks revocation or cascades evidence deletion. A stable tenant-scoped historical author anchor can retain the recorded identity while an optional separate nullable live-member pointer is cleared on removal. That pointer never grants authority. For a composite live-member FK, null only the nullable pointer on deletion, preserving the non-null tenant key. Attachment metadata remains linked by organization/source/revision, with consistent immutable identity/digest/storage metadata; no file upload/storage behavior is implemented here. Original source text is evidence, not log/error content.

Every human operation invokes the existing AuthorizationService against live membership. Acceptance requires source:submit and matching context/source organization. Volunteers submit only under their own live author membership and read only their own submitted sources. Owner/coordinator may submit for a mapped member in their organization, or an explicitly unmapped external author; read access to staff evidence requires review:write. A report-reader's aggregate permission grants no evidence access. Cross-tenant/non-owned source reads return NOT_FOUND without disclosure; revoked/stale context is denied. System actors are denied in this first slice; a future worker authority contract must be scoped before worker integration. Parsing TenantContext is never authorization. Channel/external author strings never grant authority.

Use database uniqueness/transactions to enforce race safety, not process-local locks. Persist source and source.received outbox atomically with stable event IDs, aggregate source/revision, actor and correlation provenance. An outbox row is pending durable work, not a claim that queue dispatch or delivery has happened. No external side effect occurs inside these transactions. B proposes concrete tables/key strategy before implementation and alone generates the next migration; A reviews tenant constraints and rollout order.

For E, the additive text-only WebSourceSubmission v1 contains only schemaVersion, idempotencyKey and text (nonblank, at most 20,000 UTF-16 code units). The limit is a planning default for a later HTTP adapter, not an existing endpoint. Organization, author and source timestamps will be server-derived. Files and arbitrary message URL fetching remain excluded. ReviewDecision/ReviewOutcome name the existing ReviewService shapes without changing them. ReviewQueueEntry pairs a source revision and extraction proposal with an independent optimistic review aggregate revision; runtime validation rejects tenant/source/revision mismatches. It is staff-only projection data, never authority. Evidence quote fidelity and reference ownership still require domain validation.

E's second-wave screens use independently authored synthetic data and explicit simulated callbacks. Routes are development-only and production returns 404; no authentication, durability or product milestone acceptance is claimed by fixture interaction. Actual production auth wiring, proposal persistence, ledger/need operations, worker authority, queue handlers and live provider validation each require later bounded slices. No dependency or existing wire version change is required by this decision.

Schema review clarifications: use composite primary keys containing organization_id for source roots, revisions and attachment associations; identical opaque IDs in two tenants must remain independent. Add a composite outbox-to-source-revision FK. Preserve the full validated envelope, including original ISO offset strings, independently of timestamp projections. Event IDs hash an unambiguous serialized tuple rather than delimiter-concatenated opaque IDs. Attachment identity/digest/storage metadata cannot silently change across revisions. Evidence UPDATE guards are approved, without blocking legitimate member deletion or future dispatch-state updates. Invalid envelope structure is VALIDATION; stale/gapped replacements are CONFLICT. Test revocation after a source exists, same opaque IDs across tenants, attachment mutation and replay/rollback races. No consumer dedupe or generic before/after audit table is introduced in this source-only slice.

Review disposition amendment: classify an identical stored envelope replay after current-caller authorization but before new-target validation, so removing a historical author does not invalidate staff retries. Revoked callers are still denied, and new mapped-author acceptance still requires live tenant membership. Require a non-null exact predecessor for every later revision in both application and DB checks. Map constraint/storage failures to safe typed errors without driver details/source text. Historical live pointers are database-enforced same-tenant relations, and outbox primary keys/consumer dedupe remain organization-scoped. Revision attachment links receive UPDATE protection too. Direct DELETE by the owning DB administrator is an explicit privileged-writer limitation, not a normal repository command; do not break legitimate cascades with naive DELETE guards. Production runtime/administrative privilege separation remains a later gate.

Drizzle generation limitation (review P1-02-02): installed drizzle-kit 0.31.11 / drizzle-orm 0.45.4 cannot represent the column subset of composite ON DELETE SET NULL in schema/snapshot metadata. The committed migration must retain `ON DELETE SET NULL (current_membership_id)`; plain composite SET NULL would also null organization_id and break revocation. Do not regenerate/reset migration history and silently replace this clause. Keep the schema-local explanation, membership-deletion behavior test and positive PostgreSQL `pg_constraint.confdelsetcols` assertion on source_author_current_membership_fk when authoring future migrations. The applied database behavior, not only a no-diff generator result, is the gate. No dependency upgrade or new migration is requested by this documentation.
