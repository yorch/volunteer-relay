Do not silently accept Better Auth's default member/admin aliases, comma-separated multiple roles or dynamic role definitions. Owner-only organization/member/invitation administration remains distinct from coordinator's app permissions. Exercise invite creation/cancel/accept/expiry/replay and wrong-recipient/wrong-tenant denials; do not grant membership from parsed organization IDs or arbitrary invitation bodies.
- Supply a server-only helper composing a VERIFIED Better Auth session with the existing live membership resolver, returning Result<TenantContext>. Caller userId comes from the verified session, never a request payload. Missing/invalid session is UNAUTHENTICATED; requested organization with no current membership is NOT_FOUND without tenant existence disclosure; an absent organization selection is VALIDATION. Do not treat activeOrganizationId or a parsed context as authority. Switching organization must preserve roles per membership and reject foreign/non-member selections; removed/replaced memberships and role changes take effect immediately at authorization time.
- Map unexpected session/membership dependency failures to safe typed unavailable results without driver/token details; controlled failures must resolve to Result rather than reject.
- Keep normal seeds credential-free and existing auth/source evidence/revocation behavior unchanged. Known-password demo provisioning requires a later explicit demo-only profile; do not add it to ordinary seed.
